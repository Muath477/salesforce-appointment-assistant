Automation — Autolaunched Flows

All flows are Active and agent-ready.

Create Appointment

Inputs: Contact Id, Date/Time, Service Type

Creates a record and returns the Appointment Id.

Reschedule Appointment

Inputs: Appointment Id, New Date/Time

Updates the date and sets Status = Rescheduled.

Cancel Appointment

Input: Appointment Id

Sets Status = Cancelled.

Screen Flow — Booking Interface

"Book Appointment Screen" (Active) collects Date/Time and Service Type from the user and creates the appointment record on submission. It serves as a real, user-facing booking front-end and a working alternative to the conversational AI agent.

Lightning App

"Appointment Management" Lightning App with tabs: Appointments, Contacts, Reports, Dashboards. Includes a custom tab for the Appointment object and is assigned to the System Administrator profile.

Agentforce & Conversational AI — Honest Status

Agentforce was part of the architecture from the start. Activation was constrained by the Developer Edition org (missing tenant configuration and licensing); "Agentforce Agents" returned "No matching items found" in Setup. Mitigation: the Flows were built as agent-ready actions, a fully working Screen Flow was delivered as a non-conversational booking interface, and a real, Active Einstein Bot named "Appointment Assistant" was built as the working conversational substitute. Its three dialogs — Schedule, Reschedule, and Cancel an appointment — look up the customer's real Contact and Appointment records and call the exact same Create_Appointment / Reschedule_Appointment / Cancel_Appointment Flows used everywhere else in this repo, so nothing about the automation is duplicated or faked. Everything specified in docs/AGENTFORCE.md is ready to rebuild as native Agentforce topics and actions, unchanged, the moment licensing is enabled — see §7 there for the full detail.
